Every piece of text Gears shows for your mod comes from a key you put in your mod's
`Config/Localization.csv`, looked up with the game's `Localization.Get`. Gears ships no text for
your settings. This page lists every key it will ask for and what happens when it is missing.

## The rule for missing keys

`Localization.Get` returns the key itself when it has no translation. A missing key therefore
shows up in the menu as raw text such as `myModHudScale`, never as a blank. That makes typos
easy to spot in game, and it means a `displayKey` that happens to be readable English will
"work" without a CSV row. Prefer a real key anyway so the text can be translated.

## Keys Gears looks up

| Where you write it | Key used | If empty or absent |
|---|---|---|
| `<Tab displayKey="">` | that key | falls back to the Tab's `name` (itself looked up as a key) |
| `<Tab tooltipKey="">` | that key | no tooltip |
| `<Category displayKey="">` | that key | falls back to `name` |
| `<Selector/Slider/Switch/Color/Binding displayKey="">` | that key | falls back to `name` |
| `<Caption key="">` on a setting or Category | that key | falls back to the display name |
| `<Description key="">` on a setting or Category | that key | nothing shown |
| `<LocalizationPrefix prefix="P">` on a Selector | `P` + each allowed value, and `P` + the current and selected value | the raw value is shown when there is no prefix |
| `<LocalizationPrefix prefix="P">` on a Switch | `P` + left value, `P` + right value, `P` + current and selected value | the raw value is shown |

<Callout>
  The prefix is joined to the value **without a separator**. Put any separator you want inside the
  prefix itself (`prefix="myModUnits_"`).
</Callout>

For a Selector the "value" that gets prefixed is the value **after the `ui` formatter**. With
`<Formatter ui="000">` and a prefix of `q`, the value `7` looks up `q007`.

The same lookups happen for settings created from C#: `DisplayKey`, `CaptionKey`,
`DescriptionKey` and `LocalizationPrefix` on the setting objects are the same strings.

## Worked example

```xml
<Selector name="Units" displayKey="myModUnits" type="string" defaultValue="metric">
	<List allowedValues="metric,imperial" />
	<LocalizationPrefix prefix="myModUnits_" />
	<Caption key="myModUnitsCaption" />
	<Description key="myModUnitsDesc" />
</Selector>
```

needs these rows:

```csv title="Config/Localization.csv"
Key,File,Type,UsedInMainMenu,NoTranslate,english
myModUnits,UI,Menu,x,,Units
myModUnitsCaption,UI,Menu,x,,Unit system
myModUnitsDesc,UI,Menu,x,,Which unit system the HUD uses.
myModUnits_metric,UI,Menu,x,,Metric
myModUnits_imperial,UI,Menu,x,,Imperial
```

`UsedInMainMenu` is marked `x` because the Mods menu is reachable from the main menu, before a
world is loaded. Rows without it are not available there.

## Keys that belong to Gears

The Mods window chrome (buttons, headers, the Enabled/Disabled labels, the sort options) is
localized by Gears' own `Localization.csv`. You do not need to supply any of those, and you should
not reuse their keys (`gearsUI…`, `gearsSortBy…`) for your own text.
