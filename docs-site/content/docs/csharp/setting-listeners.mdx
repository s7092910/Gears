---
title: Bind Settings with Attributes
description: Tag static fields, properties and methods with a setting path, then call BindSettingsClass to assign the settings and subscribe to their events.
---

Instead of looking up each setting by hand, tag static **fields**, **properties** and **methods**
with an attribute that names the setting, then hand the class to `BindSettingsClass`. Gears assigns
the setting to each tagged field and property, and subscribes each tagged method to the event the
attribute names.

The attributes live in `GearsAPI.Attributes`.

## The attributes

| Attribute | Goes on | Binds to |
|---|---|---|
| [`[Setting]`](/docs/reference/attributes/setting-attribute) | a static field or property | assigns the setting itself to the member |
| [`[SettingOnValueChanged]`](/docs/reference/attributes/setting-on-value-changed-attribute) | a static method | `SettingValue` changed, which means the player saved |
| [`[SettingOnSelectedChanged]`](/docs/reference/attributes/setting-on-selected-changed-attribute) | a static method | `SelectedValue` changed, which means the player moved the control in the menu |
| [`[SettingOnEnabled]`](/docs/reference/attributes/setting-on-enabled-attribute) | a static method | `Enabled` was turned on or off |
| [`[SettingOnApplied]`](/docs/reference/attributes/setting-on-applied-attribute) | a static method | the setting was applied |

Every attribute takes the setting path as its first argument. A null or empty path throws
`ArgumentException` from the attribute constructor, which surfaces the first time Gears inspects the
class. `[SettingOnValueChanged]` and `[SettingOnSelectedChanged]` take one more, optional argument,
[`invokeOnBind`](#run-a-listener-once-at-bind-time).

## Setting paths

| Settings | Format | Segments |
|---|---|---|
| Global | `"TabName.CategoryName.SettingName"` | exactly 3 |
| World | `"CategoryName.SettingName"` | exactly 2 |

The names are the `name` attributes from `ModSettings.xml`, or the names you passed to `Create…`.
They are not the display keys.

<Callout type="warn">
  **Put global and world members on separate types.** Each `BindSettingsClass` call resolves every
  tagged member on the type you hand it, using that side's segment count. A world path on a type you
  pass to the global call is reported as a bad path format, and the reverse is also true.
</Callout>

## Bind a settings class

Call `BindSettingsClass` from the matching callback:

```csharp
public void OnGlobalSettingsLoaded(IModGlobalSettings modSettings)
{
    modSettings.BindSettingsClass(typeof(MyGlobalListeners));
}

public void OnWorldSettingsLoaded(IModWorldSettings worldSettings)
{
    worldSettings.BindSettingsClass(typeof(MyWorldListeners));
}
```

One call does both halves. Gears binds the fields and properties first, then subscribes the
listeners, so a handler can safely read any member the same call binds. An
[`invokeOnBind`](#run-a-listener-once-at-bind-time) listener runs last of all, once every listener
on the type is subscribed.

Binding is opt-in. Nothing scans for these attributes until you call `BindSettingsClass`.

### Binding the same type twice

**A type is bound once, on both sides.** Gears remembers which types a settings tree has already
bound; hand it the same one again and the call does nothing at all — no field reassigned, no listener
subscribed a second time, no [`invokeOnBind`](#run-a-listener-once-at-bind-time) call. It is a no-op,
not an error, and nothing is logged.

That makes `BindSettingsClass` safe to call from anywhere you like, as often as you like. It matters
most on the world side: `OnWorldSettingsLoaded` fires once per world load *and* again on every
rejoin, against the same setting objects, so a mod binding from it would otherwise pile up a fresh
copy of every listener per load. On the global side `OnGlobalSettingsLoaded` fires once per session,
so the guard mainly covers a mod that binds the same class from two places.

Without it a second bind would add a **second** handler to every event, which then runs twice on
every change — the kind of bug that shows up as doubled work long after the call that caused it.

<Callout type="info">
  "Already bound" is tracked per settings tree, not globally, so the global and world trees keep
  their own record. Binding one type does not stop a different one binding.
</Callout>

`BindSettingsClass(null)` throws `ArgumentNullException`. Gears logs every other problem and skips
that one member, and the rest still bind.

## Bind a setting to a field or property

Tag a static field or a static property with `[Setting("…")]`, and Gears assigns the setting the
path names:

```csharp
public static class MyGlobalListeners
{
    [Setting("General.Display.HudScale")]
    private static ISliderGlobalSetting<float> hudScale;

    [Setting("General.Display.Units")]
    public static ISelectorGlobalSetting<string> Units { get; private set; }

    public static float CurrentScale => hudScale.SettingValue;
}
```

Either kind of member must be:

- **Static.** Gears reports and skips a tagged instance field or property.
- **Declared as a type the setting actually is.** Any interface or class in the setting's own
  hierarchy works: `IModSetting`, `IGlobalModSetting`, `IValueModSetting<T>`,
  `ISliderGlobalSetting<T>`, even the concrete class. Gears reports a mismatch, most often the wrong
  `T`, and leaves the member alone.

A **field** must also be assignable, so neither `readonly` nor `const`. Gears reports and skips
both.

A **property** must also have a setter. Both `{ get; set; }` and `{ get; private set; }` bind, and
Gears calls the setter, so a property with a body runs whatever logic it contains. A get-only
property, written `{ get; }` or as an expression body, has nothing to assign through, so Gears
reports and skips it.

Gears reads members only from the type you pass, so it does not find a tagged member inherited from
a base type. Two members may name the same setting. Any field initializer runs before binding, so
the bound setting wins.

Tagging an auto-property's backing field with `[field: Setting("…")]` also works and binds through
the field path. Tagging the property itself is simpler and gives a clearer error when something is
wrong.

## Bind a method to an event

A listener method must be:

- **Static.** Public and private both work, and Gears does not see instance methods.
- **Declared on the type you pass.** Gears does not scan members inherited from a base type.
- **An exact signature match for the event**, parameter types included:

| Attribute | Required signature | Works on |
|---|---|---|
| `[SettingOnValueChanged("...")]` | `static void M(IValueModSetting<T> setting, T newValue)` | global value settings |
| `[SettingOnSelectedChanged("...")]` | `static void M(IValueModSetting<T> setting, T newValue)` | global and world value settings |
| `[SettingOnApplied("...")]` | `static void M(IGlobalModSetting setting)` | global settings, including Color and Binding |
| `[SettingOnEnabled("...")]` | `static void M(IModSetting setting, bool isEnabled)` | every setting, global and world |

`T` is the setting's value type: `int` for an `int` slider, `bool` for a `bool` switch,
`UnityEngine.Color` for a color, your enum for an enum selector. The first parameter is
`IValueModSetting<T>`, not `IGlobalValueSetting<T>` or `ISliderGlobalSetting<T>`. A more derived
parameter type does not match.

`OnEnabled` is declared on `IModSetting`, so `[SettingOnEnabled]` is the one listener that works on
every setting type. It fires only when `Enabled` actually changes value, not on every assignment.

A method may carry several attributes, so one method can listen to several settings.

## Run a listener once at bind time

A listener only ever fires on a *change*, so a mod that wires one up still has to read the setting's
current value somewhere to start off in the right state. `invokeOnBind` does that for you: pass
`true` and Gears calls the method once during `BindSettingsClass`, handing it the value the event
would have carried.

```csharp
[SettingOnValueChanged("General.Display.HudScale", true)]
private static void HudScaleChanged(IValueModSetting<float> setting, float newValue)
{
    // Runs once during BindSettingsClass with the saved scale, and again on every save after that.
    MyHud.Scale = newValue;
}
```

| Attribute | `invokeOnBind: true` passes |
|---|---|
| `[SettingOnValueChanged]` | the setting's current `SettingValue`, the applied value |
| `[SettingOnSelectedChanged]` | the setting's current `SelectedValue`, what the UI shows |

It defaults to `false`, so an attribute written without it behaves exactly as before. Only these two
attributes take it — `[SettingOnApplied]` and `[SettingOnEnabled]` do not, since neither carries a
value to replay.

Gears still subscribes the method to the event as normal. The initial call is **on top of** the
subscription, not instead of it, so the handler runs again on every later change.

Named arguments read better when the path is long:

```csharp
[SettingOnSelectedChanged("General.Display.HudScale", invokeOnBind: true)]
```

### When the call happens

Gears runs every `invokeOnBind` listener at the very end of `BindSettingsClass`, after all fields,
all properties and all listeners on that type are bound. So by the time your handler runs it can
read any `[Setting]` member on the class, and anything it changes reaches the class's other
listeners.

<Callout type="info">
  The initial call ignores `Enabled`. A real `OnValueChanged` or `OnSelectedChanged` is suppressed
  while a setting is disabled, but `invokeOnBind` calls the method either way, so a mod always
  starts in sync with what is saved. Check `setting.Enabled` in the handler if that matters to you.
</Callout>

An `invokeOnBind` handler that throws is reported to the log, and binding carries on: the remaining
initial calls still run, and the rest of the class is already bound by then.

The initial call happens **once for the whole session**, on the first `BindSettingsClass` for the
type. Later calls are [skipped entirely](#binding-the-same-type-twice), the initial call along with
everything else. On a world type in particular this is not a per-world-load hook: your listener still
fires normally whenever a world load brings in a different value, but the initial call happens only
that first time.

## Example

`MyHud` below is your own class. Gears knows nothing about it.

```csharp
using GearsAPI.Attributes;
using GearsAPI.Settings;
using GearsAPI.Settings.Global;
using GearsAPI.Settings.World;
using UnityEngine;

public static class MyGlobalListeners
{
    [Setting("General.Display.HudScale")]
    private static ISliderGlobalSetting<float> hudScale;

    [Setting("General.Display.Units")]
    private static ISelectorGlobalSetting<string> units;

    // invokeOnBind: the HUD picks up the saved scale at bind time, not only on the next save.
    [SettingOnValueChanged("General.Display.HudScale", true)]
    private static void HudScaleSaved(IValueModSetting<float> setting, float newValue)
    {
        MyHud.Scale = newValue;
    }

    [SettingOnSelectedChanged("General.Display.HudScale")]
    private static void HudScalePreview(IValueModSetting<float> setting, float newValue)
    {
        MyHud.PreviewScale(newValue);
    }

    [SettingOnValueChanged("General.Display.Units")]
    private static void UnitsSaved(IValueModSetting<string> setting, string newValue)
    {
        MyHud.Units = newValue;
    }

    [SettingOnValueChanged("Colors.HUD.Accent")]
    private static void AccentSaved(IValueModSetting<Color> setting, Color newValue)
    {
        MyHud.Accent = newValue;
    }

    [SettingOnApplied("General.Display.HudScale")]
    [SettingOnApplied("General.Display.Units")]
    private static void AnythingApplied(IGlobalModSetting setting)
    {
        MyHud.Redraw();
    }

    [SettingOnEnabled("General.Display.HudScale")]
    private static void HudScaleEnabledChanged(IModSetting setting, bool isEnabled)
    {
        MyHud.ScaleOverrideActive = isEnabled;
    }
}

public static class MyWorldListeners
{
    // [Setting] works the same on both sides, with the two-segment world path.
    [Setting("Zombies.SpawnMultiplier")]
    private static ISliderWorldSetting<int> spawnMultiplier;

    // Only OnSelectedChanged exists on world settings. It fires while the host picks values.
    [SettingOnSelectedChanged("Zombies.SpawnMultiplier")]
    private static void SpawnPreview(IValueModSetting<int> setting, int newValue)
    {
    }

    // OnEnabled is on IModSetting, so it works here too.
    [SettingOnEnabled("Zombies.SpawnMultiplier")]
    private static void SpawnEnabledChanged(IModSetting setting, bool isEnabled)
    {
    }
}
```

## Log lines when a member does not bind

Every message below comes from `[Gears]`. Each one skips that member only, and the rest still bind.

### Listeners

| Message | Cause |
|---|---|
| `[SettingOnValueChangedAttribute("…")] on 'Ns.Type.Method' must use the format "tabName.CategoryName.SettingName". Skipping registration of listener.` | wrong number of path segments; a world path is `"CategoryName.SettingName"` |
| `[SettingOnValueChangedAttribute] on 'Ns.Type.Method' references unknown setting "…". Skipping registration of listener.` | no setting at that path |
| `[SettingOnApplied("…")] on '…' targets a setting that does not support OnSettingApplied (only global settings expose it). Skipping registration of listener.` | `[SettingOnApplied]` on a world path |
| `[SettingOnValueChangedAttribute("…")] on '…' targets a setting that does not expose an 'OnValueChanged' event. Skipping registration of listener.` | `[SettingOnValueChanged]` on a world setting, or either value attribute on a Binding |
| ``[SettingOnValueChangedAttribute] on '…' has an invalid signature, skipping registration of listener. Expected: static Void Method(IValueModSetting`1, Int32).`` | wrong parameter types, wrong parameter count, a non-void return, or a non-static method |
| `[SettingOnValueChangedAttribute("…")] on '…' asked for InvokeOnBind, but the setting exposes no 'SettingValue'. Skipping the initial call.` | `invokeOnBind: true` on a setting that holds no value; the listener itself is still subscribed |
| `[SettingOnValueChangedAttribute("…")] on '…' threw during its InvokeOnBind call: …` | your handler threw on its initial call; binding carries on and the other initial calls still run |

### Field bindings

| Message | Cause |
|---|---|
| `[SettingAttribute("…")] on 'Ns.Type.field' must use the format "tabName.CategoryName.SettingName". Skipping binding of field.` | wrong number of path segments; a world path is `"CategoryName.SettingName"` |
| `[SettingAttribute] on 'Ns.Type.field' references unknown setting "…". Skipping binding of field.` | no setting at that path |
| `[Setting("…")] on '…' is declared const and can never be assigned. Skipping binding of field.` | a `const` field |
| `[Setting("…")] on '…' is declared readonly and cannot be assigned. Remove readonly. Skipping binding of field.` | a `static readonly` field, or the backing field behind a `[field: Setting]` on a get-only auto-property |
| `[Setting("…")] on '…' is not static. Only static fields can be bound. Skipping binding of field.` | an instance field |
| `[Setting("…")] on '…' is declared as 'ISliderGlobalSetting<Single>' but the setting is a 'SliderSettingInt'. Skipping binding of field.` | the field's declared type does not fit the setting, usually the wrong `T` |

### Property bindings

| Message | Cause |
|---|---|
| `[SettingAttribute("…")] on 'Ns.Type.Property' must use the format "tabName.CategoryName.SettingName". Skipping binding of property.` | wrong number of path segments; a world path is `"CategoryName.SettingName"` |
| `[SettingAttribute] on 'Ns.Type.Property' references unknown setting "…". Skipping binding of property.` | no setting at that path |
| `[Setting("…")] on '…' has no setter and cannot be assigned. Give it one, even a private one. Skipping binding of property.` | a `{ get; }` or expression-bodied property |
| `[Setting("…")] on '…' is not static. Only static properties can be bound. Skipping binding of property.` | an instance property |
| `[Setting("…")] on '…' takes index parameters and cannot be assigned. Skipping binding of property.` | an indexed property, which C# cannot declare as static |
| `[Setting("…")] on '…' is declared as 'ISliderGlobalSetting<Single>' but the setting is a 'SliderSettingInt'. Skipping binding of property.` | the property's declared type does not fit the setting, usually the wrong `T` |
